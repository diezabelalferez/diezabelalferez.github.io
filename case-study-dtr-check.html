DTR CHECK: catching payroll errors before payday

A repeatable check that compares each employee's DTR against the corrected biometric printout. It lists every mismatch, with the cause and the hours at stake.

The problem

Payroll runs on the DTR. The biometric is the true record. When the two disagree, someone gets paid wrong.

I have seen this in real payroll. Two DTR pages were missing from a biometric upload. Fifteen people were affected. They were paid on the next payroll, after an incident report and a lot of follow-up.

Checking page by page is slow and easy to get wrong. So I built a check that does not skip anything.

What I built

I trigger it with two words: DTR CHECK. I give it the DTR and the corrected biometric for one pay period. It returns one report.

  1. It compares page counts and headcount first. A missing employee shows up here.
  2. It matches every employee, day by day, on Time In, Time Out and hours.
  3. It re-adds each daily column and compares it with the printed total.
  4. It names the cause of each issue, not only the changed total.
  5. It lists the fix needed before payroll is released.

The test

Result

All six errors were found. Nothing was flagged by mistake. The report opens with the page-count difference, because that points to the biggest problem.

The last error is the one people miss. Every daily row was right. Only the printed total was wrong. The check re-adds the rows, so it catches this.
